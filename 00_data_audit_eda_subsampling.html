3. Exploratory analysis

3.1 Correlation between the 14 service items

The 14 ordinal items are the core covariates for the horseshoe model in Section 3 of the project, so it matters whether they are independent. We reuse the correlation-heatmap recipe from the JAGS lab notes (image() + RColorBrewer, rather than pulling in a new plotting package just for this).

plot_corr_heatmap <- function(mat, labels = colnames(mat), title = "Correlation matrix", show_values=TRUE, digits_to_show=3) {
  pal <- colorRampPalette(rev(brewer.pal(11, "RdBu")))(100)
  layout(matrix(c(1, 2), nrow = 1), widths = c(4, 1))
  par(mar = c(7, 7, 4, 1))
  image(1:ncol(mat), 1:ncol(mat), mat,
        xlab = "", ylab = "", main = title,
        col = pal, zlim = c(-1, 1), axes = FALSE)
  axis(1, 1:ncol(mat), labels, las = 2, cex.axis = 0.8)
  axis(2, 1:ncol(mat), labels, las = 2, cex.axis = 0.8)
  box()
  
  # show correltion values within boxes
  if (show_values) {
    grid <- expand.grid(i = 1:nrow(mat), j = 1:ncol(mat))
    text(grid$i, grid$j,
         labels = round(mat[cbind(grid$i, grid$j)], digits_to_show),
         cex = 0.7)
  }
  
  # colorbar
  par(mar = c(7, 1, 4, 3))
  z <- seq(-1, 1, length.out = 100)
  image(1, z, matrix(z, nrow = 1), col = pal, axes = FALSE, xlab = "", ylab = "")
  axis(4, las = 2)
  box()
}

corr_mat <- cor(data[ordinal_vars])
plot_corr_heatmap(corr_mat, title = "Correlation between the 14 service-quality items")

Two clear blocks stand out, plus a third, weaker one:

  • Digital/online cluster: wifi, online_support, ease_booking, online_boarding (pairwise correlations 0.56–0.63).
  • Physical/onboard cluster: onboard_service, legroom, baggage, cleanliness (pairwise correlations roughly 0.4–0.6).
  • Boarding-logistics cluster: seat_comfort, time_convenient, food_drink, gate_location also move together, most likely because they share the same block of structural zeros discussed in Section 4 below (customers with an “N/A” on one tend to have it on all four).

None of this is surprising, but it is exactly the justification for the horseshoe shrinkage prior later: several of these 14 covariates are near-substitutes for one another, so a model that shrinks the redundant ones towards zero is preferable to plain vague-prior logistic regression with all 14 included.

4. The delay pair: decorrelating arrival from departure delay

cor(data$dep_delay, data$arr_delay)
## [1] 0.9652912
ggplot(data, aes(x = dep_delay, y = arr_delay)) +
  geom_point(alpha = 0.03) +
  geom_smooth(method = "lm", se = FALSE, color = "red") +
  labs(title = "Arrival vs. departure delay",
       x = "Departure delay (min)", y = "Arrival delay (min)") +
  theme_minimal()

A correlation of 0.965 means including both raw variables in a regression is close to duplicating one predictor — exactly the near-collinearity the horseshoe prior is meant to handle, but there is a cheaper fix for this specific pair. We regress arr_delay on dep_delay and keep the residual as a second covariate: by the defining property of least squares, a residual is orthogonal to every column of the design matrix used to produce it, so this new variable is uncorrelated with dep_delay by construction — no shrinkage prior needed to discover that.

delay_fit <- lm(arr_delay ~ dep_delay, data = data)
data$arr_delay_extra <- resid(delay_fit)

cor(data$arr_delay_extra, data$dep_delay)
## [1] -1.974482e-15

As a sanity check, this is nearly the same information as the naive arr_delay - dep_delay “minutes gained or lost in the air”, since the estimated slope is close to 1:

coef(delay_fit)
## (Intercept)   dep_delay 
##   0.7574643   0.9788491
excess <- data$arr_delay - data$dep_delay
cor(excess, data$arr_delay_extra)
## [1] 0.9968262

We keep arr_delay_extra (exactly orthogonal to dep_delay) rather than the naive difference (only approximately so) as the second delay covariate for Sections 2-3, alongside dep_delay itself.

Four items — time_convenient, food_drink, seat_comfort, entertainment have a non-trivial block of zeros (2-5% of rows), well above the near-zero rates for the rest. A real “1” (very dissatisfied) and a coded “0” (not applicable, e.g. no in-flight entertainment on that aircraft) are different things, but disentangling them would need a zero-inflated / mixture likelihood for each item. We flag this here and treat it as a robustness check later (Section 5 of the project: refit excluding these rows and see whether conclusions move), rather than building extra model complexity into the main analysis now.

6. The subsampling decision

The full file has 129487 rows (after dropping the 393 with missing arr_delay), while the project brief describes a curated 1,000-row extract. We draw a stratified training subsample of \(n\approx 1200\) — matching the brief’s intended scale and keeping every MCMC run in later sections fast — and keep essentially all remaining rows as a held-out test set for the prediction exercise in Section 6. Stratifying on satisfaction and cabin_class (6 strata) keeps the subsample representative of the population on exactly the variables the whole analysis is about.

stratified_sample <- function(pop, strata_vars, n_target, seed = 2026) {
  set.seed(seed)
  frac <- n_target / nrow(pop)
  pop %>%
    group_by(across(all_of(strata_vars))) %>%
    slice_sample(prop = frac) %>%
    ungroup()
}

train <- stratified_sample(data, c("satisfaction", "cabin_class"), n_target = 1200, seed = 2026)
test  <- data %>% filter(!row_id %in% train$row_id)

nrow(train); nrow(test)
## [1] 1197
## [1] 128290

Summary

Before touching a single prior: the response is close to balanced, the 14 service ratings form 2-3 correlated blocks (motivating shrinkage rather than using all 14 naively), the two delay variables are near-duplicates (fixed by keeping dep_delay and an orthogonal residual arr_delay_extra), a handful of items carry a structural-zero block worth revisiting later, and a stratified ~1200-row training subsample keeps the MCMC-based sections fast while ~128290 held-out rows give a low-variance out-of-sample check.
